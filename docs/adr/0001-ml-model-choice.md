# ADR-0001：风险预测用 LightGBM，而不是「直接把表格丢给大模型」

- 状态：已采纳
- 日期：2026-09-25
- 相关代码：`server-ml/train.py`、`server-ml/feature.py`、`server/src/services/ml-client.ts`

## 背景

系统需要把「睡眠 / 运动 / 压力 / 饮食 / 作息 / 久坐」这类结构化生活方式数据映射成
**可解释、可复现、可离线判定**的风险等级。可用方案有三类：

1. 梯度提升树（LightGBM）；
2. 把特征拼成提示词交给大模型（LLM）直接输出等级；
3. 纯规则引擎（阈值 + 加权打分），不训练模型。

## 决策

**用 LightGBM 做分级**，并用 SHAP 提供归因；LLM 只负责**自然语言表达**（画像文案、
计划文案、复评说明），不参与等级判定。规则引擎作为独立的一层保留，既是降级兜底，
也是安全底座（急症分流）。

## 理由

- **可解释**：SHAP 能给出「哪个特征把风险推高了多少」，LLM 给不出稳定的数值归因；
  比赛与临床沟通都需要「可追溯的判定依据」。
- **可复现**：固定种子 + 锁定版本即可复现同一结果（见 `server-ml/README.md`）；
  LLM 同输入两次输出都可能不同——这在本项目里是优点（用于文案）也是缺点（用于判定）。
- **可按分布监控**：模型判定的前提是「线上输入分布与训练分布一致」，
  这件事只能用 PSI 这类统计手段监控（见 ADR-0004），LLM 无法承载。
- **降级可验证**：`GET /health/risk` 会如实标注 `source: "ml" | "rule" | "insufficient"`，
  降级与否现场可一键核对（`server/src/routes/health/mlDrift.ts`、`mlStatus.ts`）。

## 已知代价（必须如实交代）

- 标签是**规则蒸馏**的（`train.py::rule_label`），Accuracy 0.98 / AUC 0.999 是自证指标，
  不代表泛化能力。这一点写进了 `docs/model-report.md` 的「指标偏高的正确解读」。
- 冷启动只有合成数据，`training_mode = synthetic_only`；问卷攒够 100 份才切
  `real_priority`，且标签仍来自规则，不是医学标注。

## 被否方案

- **LLM 直接判定等级**：不可复现、不可解释、不可做分布监控，且断网即失效。
- **纯规则引擎**：可解释但与「AI 预测」的核心卖点冲突，且无法回答特征重要性；
  但它被保留为安全兜底层，并不算被否决。

## 影响

- 多了一个独立 Python 服务（端口 8000），需要 `pnpm dev:all` 一起启动。
- 模型产物是二进制/文本文件，必须防止 Git 换行符破坏（已由 `.gitattributes` 锁定）。
