# ADR-0003：隐私授权独立建表，脱敏在小样本阈值处强制生效

- 状态：已采纳
- 日期：2026-09-25
- 相关代码：`server/src/routes/health/authorizations.ts`、`server/shared/health-privacy.ts`、
  `server/shared/health-analytics.ts`、`server/src/routes/health/audit.ts`

## 背景

"群体健康看板"要把个体数据聚合成群体结论。聚合功能天然与隐私冲突：
只要分组足够细，聚合结果就能反推出个体（例如某院系只有 1 个人，
"该院系平均睡眠 5.2 小时"等于直接说出这个人的数据）。

## 决策

1. **授权独立建模**：共享授权单独建表（`user_privacy.allow_shared`），
   而不是塞进 `profiles` 的某个字段——授权是独立生命周期，可随时撤销且必须可审计。
2. **默认不共享**：未授权用户的数据**完全不参与**任何统计，不是"匿名参与"。
   看板同时显示 `excludedByPrivacy` 人数，让"被排除"这件事本身可见。
3. **小样本强制隐藏**：任一分组样本数 < `ANALYTICS_MIN_SAMPLE`（5）时，
   该分组的值一律返回 `null`，前端显示"样本不足，已隐藏"，**绝不用 0 兜底**。
   阈值定义在 `server/shared/health-analytics.ts`，是前后端唯一来源。
4. **导出与页面同口径**：CSV/JSON 导出走同一套脱敏函数，导出动作写审计日志。

## 理由

- 用 0 兜底会把"不知道"说成"是 0"，既误导统计也破坏隐私承诺；
  返回 `null` 才能让前端如实显示"已隐藏"。
- 阈值只有一处定义，就不会出现"页面隐藏了、导出却泄露"的经典漏洞。

## 被否方案

- **匿名聚合（去掉 user_id 后统计）**：小样本下不等于脱敏，
  5 人的分组仍然可反推；必须有样本量阈值。
- **把授权放在 profiles 表里**：撤销授权会污染档案更新时间，审计也查不清"谁在何时授权"。

## 影响

- 看板在样本少时会显示大面积"已隐藏"，演示时看起来"数据很少"——
  这是设计使然，答辩时应主动解释，而不是为了好看关掉阈值。
