## 一、交付概述

系统已从「纯前端 mock」改造为**前后端一体的真实应用**：Vue3 + Vite 前端 + Express + better-sqlite3 服务端，JWT 鉴权、bcrypt 密码、数据落 SQLite，生产环境由 Express 单端口托管前端产物。

| 维度     | 交付状态                                                                                                  |
| -------- | --------------------------------------------------------------------------------------------------------- |
| 运行方式 | 开发双终端（8848 + 3000）／生产单端口（`pnpm start` → <http://localhost:3000>）／Docker                   |
| 数据持久 | SQLite `server/data/zhikang.db` + 头像 `server/data/uploads`，**进程重启不丢**                            |
| 权限     | RBAC（admin / common）：动态路由过滤 + 接口级 `adminOnly` + 数据 `user_id` 隔离                           |
| AI 方案  | A 本地规则引擎（断网可用，唯一源码 `server/shared/health-engine.ts`）/ B 火山方舟大模型（Key 仅存服务端） |
| Mock     | **已全部移除**（`mock/`、`vite-plugin-fake-server`、`@faker-js/faker`、`src/api/mock.ts`）                |
| 回归结果 | 接口回归 **120 项全通过**；重启持久化 **9 项全通过**；`pnpm typecheck` EXIT=0                             |

## 五、复现验收步骤

```bash
# 1. 类型检查（两个都要 EXIT=0）
pnpm typecheck
npx tsc -p server/tsconfig.json --noEmit

# 2. 构建 + 单端口启动（前端 + /api + /uploads 同一端口）
pnpm build
pnpm start                      # 浏览器打开 http://localhost:3000

# 3. 接口全链路回归（服务需已运行；120 项断言，退出码 0 即全部通过）
node server/scripts/regress-api.mjs

# 4. 开发模式（另开终端，与上面二选一）
pnpm dev:server                 # 终端 1：后端 3000
pnpm dev                        # 终端 2：前端 8848（/api、/uploads 已代理）
```

回归脚本可用 `BASE=http://<内网IP>:3000` 指向其他机器/端口。

## 六、遗留问题与已知偏差

| #   | 项目                             | 说明                                                                                                                                                                                                          | 影响                                     |
| --- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 1   | **Docker 未在本机验证**          | 本机未安装 docker，`Dockerfile` / `docker-compose.yml` 按方案编写但**未实际构建运行**；首次使用建议 `docker compose up -d --build` 后确认 `server/data` 卷挂载与健康检查                                      | 中：部署路径需在有 docker 的环境复验一次 |
| 2   | `pnpm start` 用 `tsx` 启动       | 方案原文为 `node server/src/index.ts`；Node 24 原生类型剥离不解析 `./x.js → x.ts`，实测报 `ERR_MODULE_NOT_FOUND …/server/src/env.js`，故改用 `tsx`（已从 devDependencies 移入 dependencies 并在 README 说明） | 低：行为与方案一致，仅启动器不同         |
| 3   | 两个前端 API 无调用方            | `src/api/health.ts` 的 `exportHealthRecords`、`sendHealthChat` 无页面引用（历史页导出走 `getHealthRecords({pageSize:100000})`）；接口本身可用                                                                 | 低：死代码，可后续清理                   |
| 4   | 导入失败口径为 200 + `errors[]`  | 行级校验失败返回 HTTP 200 + `errors[]`（非 400），因前端 http 封装对非 2xx 直接 reject、导入页只 `try/finally`，400 会让页面静默失败                                                                          | 低：有意选择，已在代码注释说明           |
| 5   | 导入页未渲染 `errors[]` 行级明细 | `import/index.vue` 仅展示 `data.fail` 汇总，未逐行展示失败行号与原因（服务端已返回）                                                                                                                          | 低：UI 增强项                            |
| 6   | 无自动化测试框架                 | 仓库未引入 vitest 等，回归以脚本 `server/scripts/regress-api.mjs` 形式提供（120 项断言）                                                                                                                      | 低：已可一键复跑                         |
