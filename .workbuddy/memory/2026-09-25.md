### 最关键的实测发现（P0，答辩前必须修）

1. **模型文件被 Git CRLF 破坏**：`server-ml/model/lgbm.txt` 6995 行全为 `\r\n`（全局 `core.autocrlf=true`，`.gitattributes` 未标记模型文件）。LightGBM 加载报 `Model format error, expect a tree here`；转 LF 后加载成功（360 棵树）。→ Windows 上 clone 仓库 AI 预测直接失效，静默降级为规则引擎。
2. **标签是规则蒸馏**：`train.py` 的 `rule_label()` 给合成数据打标，标签是特征的确定性函数 → Accuracy 0.981 / AUC 0.999 是自证指标，无泛化意义。`health_survey` 实测 **0 条**。
3. **SHAP 方向计算错误**：`explain.py:36` 用 `sv.mean(axis=1)` 取全类平均（应为预测类）。实测健康人输出"睡眠 8h 升高风险""压力 1 升高风险"，已渲染到 `risk/index.vue`。
4. **全零特征判高风险 90.4%**：`feature.py` 缺失补 0，而 `student_profile` 实测 0 条 → study/sedentary/bedtime 全传 0，偏离训练分布（7/8/23）。
5. **KMeans 无效**：silhouette=0.066（k=3~6 全在 0.05-0.066），簇心差异极小；`metadata.json` 键为 `version` 而代码读 `model_version` → 版本永远回退默认值。
6. **RAG 路径错误**：`health-knowledge.ts:31` 用 `process.cwd()/src/data/...`，实际文件在 `server/src/data/`，从根目录启动（根 package.json 的 `dev:server`）时永久失效。
7. **Agent 无闭环**：`planAgent.ts:12` 硬编码 `summary: ""`；Plan 结果无入库入口；Review 只按 planId 查库。
8. **评分不归一化**：`health-engine.ts:596-601` 未除以已测权重 → 仅录血压 200/120 得 25 分判"低风险"。
9. **急症分流假阳性**："我没有胸痛" → 触发 120 急救卡（无否定词处理）。
10. **ML 服务默认不启动**（8000 未监听），README 快速开始未提及，当前系统跑在规则引擎降级模式。

### 其它确认

- 唯一无鉴权业务接口：`/health/cluster-stats`（`clusterStats.ts:15`）。其余均通过 `router.use(authMiddleware)` 或行内挂载（daily.ts / ai/* 是用 router.use，不要误判）。
- Review Agent 越权：`calcCompletion(planId)` 不带 user_id。
- 测试 376 用例全绿，但存在"自证"（用 analyzeHealth 验证调用 analyzeHealth 的聚合）与静态字符串断言问题。
- 前端多处"假 AI"：ai-profile 进度条恒 done、报告页 AI 生成进度伪造、HealthFactorChart 关键词计数、dashboard 五维画像硬编码。
